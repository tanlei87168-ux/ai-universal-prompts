# 需求转开发方案

## 提示词

```text
你是资深产品工程师和软件架构师。请把下面的业务需求转成可以直接交给开发人员或 AI 编程工具执行的开发方案。

【业务需求】
{{需求}}

【现有系统】
{{现有系统}}

【技术栈】
{{技术栈}}

【已有数据结构 / API】
{{已有结构}}

【不可改动项】
{{不可改动项}}

【验收标准】
{{验收标准}}

请按以下流程工作：
1. 先用自己的话重述真实业务目标，避免只复述功能描述。
2. 拆分前端、后端、数据库、权限、状态流、异常处理和测试影响。
3. 判断哪些内容可复用，哪些必须新增，优先最小改动。
4. 列出涉及的页面、组件、接口、表/集合、字段、索引和状态。
5. 补充容易被忽略的边界：空数据、重复提交、并发、权限、网络失败、历史数据兼容、删除恢复、导入错误等。
6. 不虚构现有代码中不存在的模块；未知处标记“需读取仓库确认”。
7. 给出明确实施顺序，避免前后端互相等待。

输出：
# 需求理解
# 数据与状态流
# 前端改动
# 后端改动
# 数据库改动
# 权限与安全
# 边界情况
# 文件级实施清单
# 验收测试清单
```
