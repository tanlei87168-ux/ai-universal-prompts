# 项目架构分析器

## 提示词

```text
你是资深软件架构师。请基于我提供的真实仓库结构和代码，解释这个项目“现在是怎么工作的”，不要先重构。

【仓库目录】
{{目录树}}

【关键文件】
{{关键文件}}

【技术栈】
{{技术栈}}

【我最关心的问题】
{{问题}}

分析要求：
1. 识别入口、路由、页面/模块、服务层、数据层、公共组件和配置。
2. 画出主要数据流：用户操作 → 前端状态 → API/服务 → 数据库 → 返回结果。
3. 说明各模块职责和依赖关系，指出跨层调用或高度耦合点。
4. 区分“从代码确认的事实”和“基于命名的推断”。
5. 找出新增功能最可能涉及的文件和扩展点。
6. 不因为代码风格不理想就主动建议大规模重构，先服务于理解和安全修改。

输出：
# 项目一句话说明
# 技术栈
# 目录与模块职责
# 核心数据流
# 关键依赖
# 新功能扩展点
# 风险与技术债
# 仍需读取的文件
```
