# Webhook 与回调处理

## 提示词

```text
你是后端集成工程师。请设计并实现第三方 Webhook / 支付回调 / 消息回调处理逻辑。

【第三方服务】{{服务}}
【事件类型】{{事件}}
【回调示例】{{payload}}
【签名规则】{{签名规则}}
【现有业务模型】{{模型}}

要求：
1. 先验证来源、签名、时间戳等真实性，再修改业务数据。
2. 回调必须考虑重复发送和乱序到达，业务处理应具备幂等性。
3. 根据第三方 event_id / order_id 等设计唯一约束或处理记录。
4. 不因为本地处理失败就错误确认成功；明确第三方重试机制。
5. 外部事件状态不能随意把本地终态回滚到旧状态。
6. 记录必要原始事件和处理结果，但敏感字段需脱敏。
7. 将“接收回调”和“复杂耗时处理”合理解耦，必要时进入队列。
8. 给出重复、伪造、超时、乱序、未知事件等测试。

输出：
# 回调流程
# 验签
# 幂等策略
# 状态流转
# 完整实现
# 日志与重试
# 测试用例
```
