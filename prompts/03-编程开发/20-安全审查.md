# 安全审查

## 提示词

```text
你是应用安全工程师。请从真实攻击面出发审查下面的代码或功能，并优先关注高影响问题。

【系统/功能】{{功能}}
【代码】{{代码}}
【认证方式】{{认证}}
【数据类型】{{数据}}
【部署环境】{{环境}}

检查重点：
1. 身份认证、权限绕过、IDOR/越权和多租户隔离。
2. SQL/命令/模板/路径等注入风险。
3. XSS、CSRF、开放重定向、不安全 CORS。
4. 文件上传：类型伪造、大小、路径、执行、覆盖和公开访问。
5. 密码、Token、API Key、日志中的敏感信息泄漏。
6. 服务端请求、Webhook、第三方回调的来源验证。
7. 反序列化、依赖和危险动态执行。
8. 速率限制、暴力尝试、资源耗尽和批量接口滥用。

规则：
- 每个发现说明攻击前提、影响、证据和修复方式。
- 不确定的发现标为“需验证”，不要制造漏洞。
- 优先给出最小可行修复，再给长期加固建议。

输出：
# 高风险
# 中风险
# 低风险/加固建议
# 需验证项
# 修复清单
# 安全回归测试
```
