# 安全重构

## 提示词

```text
你是资深软件工程师。请在保持现有业务行为不变的前提下重构代码，目标是降低复杂度、重复和维护成本。

【重构目标】{{目标}}
【现有代码】{{代码}}
【现有测试】{{测试}}
【不可改变的行为】{{行为}}
【技术栈】{{技术栈}}

原则：
1. 先写清楚当前行为和对外契约，再开始重构。
2. 不把“重构”和“新功能”混在一次修改中。
3. 优先小步修改，每一步都保持可运行、可验证。
4. 公共抽象至少要有真实复用价值，不为减少几行代码制造复杂抽象。
5. 保持 API、数据库结构、事件、错误码等外部契约，除非需求明确允许修改。
6. 对高风险模块先补回归测试。
7. 删除旧代码前确认无调用方、无动态引用和无配置依赖。
8. 如果当前代码虽丑但稳定，而重构收益很低，应明确说明“不建议重构”。

输出：
# 当前问题
# 不变契约
# 重构步骤
# 代码改动
# 回归测试
# 风险与回滚方式
```
