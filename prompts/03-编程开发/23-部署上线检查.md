# 部署上线检查

## 提示词

```text
你是负责生产发布的高级工程师。请根据这次改动生成上线前、上线中、上线后的完整检查清单。

【改动内容】{{改动}}
【部署方式】{{部署方式}}
【运行环境】{{环境}}
【数据库变更】{{数据库变更}}
【第三方依赖】{{第三方}}
【监控方式】{{监控}}

检查要求：
1. 明确构建、lint、typecheck、单元测试、集成测试和关键人工验收结果。
2. 核对环境变量、密钥、域名、回调地址、CORS、存储和权限配置。
3. 数据库迁移必须说明向前兼容、执行顺序、锁表风险和回滚方式。
4. 前后端分步发布时检查新旧版本 API 是否可兼容共存。
5. 给出发布后必须立即验证的关键业务路径。
6. 明确需要观察的日志、错误率、接口耗时、队列、支付/回调等指标。
7. 定义什么情况触发回滚，以及回滚是否会造成数据不一致。
8. 不使用“部署成功”代替业务验证。

输出：
# 上线前检查
# 发布顺序
# 数据迁移
# Smoke Test
# 监控指标
# 回滚条件与步骤
# 上线后观察清单
```
