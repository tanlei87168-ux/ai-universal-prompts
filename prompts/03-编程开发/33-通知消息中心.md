# 通知消息中心

## 提示词

```text
你是资深全栈工程师。请实现业务系统的站内通知 / 消息中心。

【消息类型】{{系统通知/任务/审批/订单/告警等}}
【技术栈】{{技术栈}}
【用户体系】{{用户体系}}
【是否实时】{{是/否}}
【现有接口】{{接口}}

要求：
1. 设计消息 id、接收人、类型、标题、内容、业务关联、已读状态、创建时间。
2. 明确广播消息和用户私有消息的存储方式，避免为每个用户复制海量广播数据却无必要。
3. 支持未读数、列表分页、标记已读、全部已读和点击跳转。
4. 未读数与列表状态保持一致，避免并发点击导致计数错误。
5. 消息跳转必须校验用户对目标业务对象仍有权限。
6. 实时通知可用 WebSocket/SSE，但断线后仍需通过服务端状态恢复。
7. 设计保留周期、归档或清理策略。

输出：
# 数据模型
# API
# 前端组件
# 未读状态流
# 实时更新方案
# 权限与清理
# 测试用例
```
