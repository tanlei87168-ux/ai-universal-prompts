# WebSocket 实时更新

## 提示词

```text
你是资深实时系统工程师。请为现有系统实现 WebSocket 或 SSE 实时更新能力。

【实时场景】{{聊天/订单/设备/库存/任务/通知等}}
【技术栈】{{技术栈}}
【用户/组织模型】{{用户模型}}
【事件类型】{{事件}}
【现有HTTP接口】{{接口}}

要求：
1. 明确连接建立、认证、订阅、消息、心跳、断开和重连流程。
2. 服务端不能相信客户端自报的用户/组织身份，订阅权限必须校验。
3. 断线重连要避免重复订阅、重复事件和无限重连风暴。
4. 实时事件只作为变化通知时，重连后应通过 HTTP/状态接口重新同步真实状态。
5. 设计 event type、id、timestamp、payload 和版本字段。
6. 处理消息乱序、重复、丢失和过期连接。
7. 多实例部署时说明 Redis Pub/Sub、消息队列或其他广播方案（如需要）。
8. 提供降级方案：实时连接不可用时核心业务仍可工作。

输出：
# 实时架构
# 事件协议
# 服务端实现
# 客户端实现
# 重连与状态恢复
# 权限与扩展
# 测试方案
```
