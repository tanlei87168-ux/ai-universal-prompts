# Prompt 分类与维护规范

本仓库采用 **一级分类 → 二级导航 → 具体 Prompt → 标签/用途** 的结构。

## 一级分类

一级分类用于回答“这个 Prompt 主要解决哪一类问题”。当前固定为 15 类：

00 万能提示词、01 办公效率、02 写作创作、03 编程开发、04 AI绘画、05 AI视频、06 自媒体运营、07 电商运营、08 销售与客服、09 商业分析、10 教育学习、11 法律、12 生活助手、13 AI智能体、14 研究与信息分析、15 营销与增长。

只有当新方向无法合理归入现有大类，并且预计至少能形成 10 个稳定 Prompt 时，才新增一级分类。

## 二级导航

当单个目录超过约 20 个 Prompt 时，应增加该目录的 README，并按能力或使用场景分组。二级导航优先使用链接分组，不轻易移动历史文件，避免破坏已有外链。

## 文件命名

统一格式：

~~~text
NN-清晰具体的任务名.md
~~~

规则：
1. 同一目录编号必须唯一。
2. 文件名描述“任务”，不要只写模糊角色名。
3. 已有链接较多的文件尽量不改路径；必须调整时先创建新路径并同步更新索引。
4. 重复 Prompt 优先合并到信息更完整的正式版本，不长期保留多个近似副本。

## Prompt 内容建议结构

简单 Prompt 可保持短小；复杂 Prompt 推荐包含：

- 适用场景
- 角色
- 输入变量
- 任务目标
- 工作流
- 约束
- 输出格式
- 质量检查
- 失败/边界处理

## 可选 Front Matter

新增长 Prompt 可逐步采用：

~~~yaml
---
title: 示例
category: AI绘画
subcategory: 商业设计
tags:
  - 海报
  - 电商
  - 品牌
difficulty: beginner
---
~~~

暂不要求一次性修改所有历史文件，避免为了格式统一制造大规模无价值变更。

## 新增 Prompt 的检查清单

- 是否与现有 Prompt 高度重复？
- 应该放在哪个一级分类？
- 目录编号是否唯一？
- 名称是否能让用户一眼知道用途？
- 是否已加入 prompts/README.md？
- 大目录的分类 README 是否同步更新？
- 是否存在真实输入、边界、失败处理和验收要求？
- 是否避免虚构数据、工具、权限、来源和执行结果？
